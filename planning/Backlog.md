## SS-01 — Согласовать модель данных и API

**Исполнитель:** Backend lead; ревью Frontend lead. **Даты:** 05.10–18.10.2026.

Описать Group, Member, Expense, ExpenseShare, Settlement; определить IDs, связи,
JSON-схемы, правила доступа и формат ошибок. Использовать прототип как основу вычислений.

**Приёмка:** опубликован контракт четырёх endpoints из Architecture; есть примеры
успешных и ошибочных ответов; Frontend и QA согласовали контракт в карточке.

## SS-02 — Спроектировать основной пользовательский сценарий

**Исполнитель:** Frontend lead. **Даты:** 05.10–18.10.2026.

Подготовить макеты создания группы, ввода расхода, списка балансов и возврата долга.
Учесть пустые состояния, загрузку, неверную сумму и отсутствие доступа.

**Приёмка:** сценарий трёх друзей показан от создания группы до расчёта;
поля согласованы с Backend; есть отображение сумм с двумя знаками после запятой.

## SS-03 — Реализовать хранение групп и расходов

**Исполнитель:** Backend developer. **Даты:** 19.10–01.11.2026.

Создавать группы и расходы через API, сохранять данные в базе, проверять членство.

**Приёмка:** данные переживают перезапуск; неизвестный участник и отрицательная
сумма отклоняются; пользователь другой группы не читает и не изменяет расходы;
сценарии создания и отказа покрыты интеграционными тестами.

## SS-04 — Подключить расчёт долей и балансов к API

**Исполнитель:** Backend developer. **Даты:** 02.11–15.11.2026.

Переиспользовать целочисленный расчёт из прототипа, получать данные из хранилища.

**Приёмка:** 100 копеек делятся на 34/33/33; сумма балансов равна нулю;
пример ужина и такси даёт +170000/−40000/−130000 коп.; контрактный тест проверяет API.

## SS-05 — Реализовать взаиморасчёты и подтверждение возврата

**Исполнитель:** Backend developer. **Даты:** 16.11–29.11.2026.

Выдавать предложения переводов и сохранять подтверждённые возвраты.
Определить, кто вправе подтверждать получение, и защитить повторную отправку запроса.

**Приёмка:** предложения погашают все балансы; повтор с тем же ключом идемпотентности
не меняет баланс второй раз; чужой участник не подтверждает возврат;
перевод не считается исполненным только потому, что попал в список рекомендаций.

## SS-06 — Реализовать формы группы и расходов

**Исполнитель:** Frontend developer. **Даты:** 16.11–29.11.2026.

Создать формы по SS-02 и подключить API. До готовности Backend разрешены mock-ответы,
но задача закрывается только после интеграции с настоящим API.

**Приёмка:** группа и расход создаются в браузере; есть выбор плательщика и получателей;
ошибка API показана рядом с полем; повторное нажатие во время отправки заблокировано;
сохранённый расход отражается в обновлённом балансе.

## SS-07 — Показать балансы и возврат долга в интерфейсе

**Исполнитель:** Frontend developer. **Даты:** 30.11–13.12.2026.

Показать «вам должны», «вы должны», список предложенных переводов и подтверждение возврата.

**Приёмка:** направление долга не перепутано; суммы совпадают с API;
подтверждение обновляет экран; нулевой баланс показывает «Вы рассчитались»;
ошибка сохранения не отображает ложный успешный результат.

## SS-08 — Подключить self-hosted runner и CI

**Исполнитель:** DevOps engineer. **Даты:** 05.10–18.10.2026.

Зарегистрировать локальный runner с меткой `splitshare-private` в отдельном приватном CI-репозитории; опубликовать подготовленный
workflow; обеспечить тестирование, сборку и исполнение артефакта.

**Приёмка:** есть ссылка на успешный Actions run и commit SHA; задание выполнено
на локальном runner; тесты прошли; `splitshare.pyz` запускается; артефакт доступен
для скачивания. По мере расширения приложения линия дополняется интеграционными проверками.

## SS-09 — Проверить сквозной сценарий и ошибки

**Исполнитель:** QA engineer. **Даты:** 14.12–20.12.2026.

Проверить в браузере создание группы, два расхода, балансы и подтверждение возвратов.
Проверить плохой ввод, отсутствие доступа, двойную отправку и перезапуск приложения.

**Приёмка:** воспроизводимые тесты проходят на собранной версии; результат
зафиксирован с commit SHA; найденные блокирующие дефекты исправлены и перепроверены.

## SS-10 — Подготовить выпуск и демонстрацию

**Исполнитель:** Release owner; согласование Product Owner. **Даты:** 21.12–27.12.2026.

Собрать релиз, актуализировать wiki, подготовить демонстрационные данные и провести показ.

**Приёмка:** выпущена версия с воспроизводимой сборкой; есть ссылка на успешный CI;
приложение запущено локально; сценарий работает; ограничения версии перечислены;
wiki, доска и квартальный план соответствуют фактическому состоянию.
