# Команды и процесс

Используем Scrum: шесть общих двухнедельных спринтов. Межкомандную координацию
организуем по принципу Scrum of Scrums. Для координации используются общая цель спринта и контроль межкомандных зависимостей.

## Команды

| Команда | Ответственность | Роль представителя |
|---|---|---|
| Backend | Группы, расходы, расчёты, контракты API | Backend lead |
| Frontend | Сценарии, формы, отображение балансов | Frontend lead |
| QA/DevOps | Тесты, runner, интеграция и выпуск | QA/DevOps lead |

Product Owner определяет приоритеты; Scrum Master помогает устранять препятствия.
Команды описывают зоны ответственности при развитии продукта. Участники репозитория: eductionnn-netizen и MrDeryf.
Если участников мало, один человек может совмещать несколько ролей.

## Доска

`Backlog → Ready → In Progress → Review → Done`

- **Backlog:** идея или задача без готового согласованного объёма.
- **Ready:** критерии приёмки определены, обязательные зависимости выполнены.
- **In Progress:** назначен исполнитель, работа началась; максимум 3 задачи на команду.
- **Review:** открыт PR, код готов к проверке; максимум 2 задачи.
- **Done:** review принят, тесты пройдены, PR объединён, документация обновлена.

Блокировку отмечаем отдельной меткой `blocked`, не скрывая исходный этап.
В карточке пишем ссылку на блокирующую задачу, владельца и ожидаемую дату решения.

## Ритм

1. В начале спринта — планирование и единая цель.
2. Ежедневно — короткая синхронизация внутри команды.
3. Дважды в неделю — Scrum of Scrums: зависимости, изменения контрактов, блокировки.
4. В конце спринта — общее демо интегрированного результата и ретроспектива.

## Связь доски с Git

Ветка: `codex/ss-03-expenses`. PR содержит ссылку на Issue и описание проверки.
Номера задач SS-01–SS-10 соответствуют Issues #1–#10. PR содержит ссылку на задачу, описание поведения и результат проверки.

Цикл разработки: задача → ветка → изменение → PR → проверка → merge → Done. Незавершённые функции остаются в Backlog. Подготовленные задачи без невыполненных зависимостей можно переводить в Ready.

## Definition of Ready и Done

| Ready | Done |
|---|---|
| Понятный результат и критерии приёмки | Критерии приёмки проверены |
| Есть оценка и ответственная роль | Код проверен, тесты пройдены |
| Известны зависимости | Изменение объединено в основную ветку |
| Согласован необходимый контракт | Документация соответствует реализации |
