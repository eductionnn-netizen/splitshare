# Команды и процесс

Разработка разделена на шесть двухнедельных спринтов. Команды согласуют общую цель
спринта и обсуждают зависимости на встречах Scrum of Scrums.

## Команды

| Команда | Ответственность | Роль представителя |
|---|---|---|
| Backend | Группы, расходы, расчёты, контракты API | руководитель Backend |
| Frontend | Сценарии, формы, отображение балансов | руководитель Frontend |
| QA/DevOps | Тесты, runner, интеграция и выпуск | руководитель QA/DevOps |

Владелец продукта определяет приоритеты, Scrum Master помогает решать организационные вопросы.
Участники проекта: eductionnn-netizen и MrDeryf. Роли распределяются при планировании спринта.

## Доска

`Backlog → Ready → In Progress → Review → Done`

- **Backlog:** задачи, ожидающие уточнения и планирования.
- **Ready:** критерии приёмки определены, обязательные зависимости выполнены.
- **In Progress:** назначен исполнитель, работа началась; максимум 3 задачи на команду.
- **Review:** открыт запрос на слияние (PR), код готов к проверке; максимум 2 задачи.
- **Done:** проверка кода завершена, тесты пройдены, изменения объединены, документация обновлена.

Блокировку задаём через Relationships → Blocked by / Blocking, сохраняя исходный статус.
В карточке указываем владельца зависимости и ожидаемую дату решения.
Связь хранится в обе стороны: зависимая задача показывает Blocked by, предшествующая — Blocking.

## Рабочие встречи

1. В начале спринта — планирование и единая цель.
2. Ежедневно — короткая синхронизация внутри команды.
3. Дважды в неделю — Scrum of Scrums: зависимости, изменения контрактов, блокировки.
4. В конце спринта — показ работающей версии и ретроспектива.

## Связь доски с Git

Для задачи создаётся отдельная ветка, например `codex/ss-03-expenses`. В запросе на
слияние указываются задача, внесённые изменения и результаты проверки.
Номера SS-01–SS-10 соответствуют Issues #1–#10.

После проверки кода и успешного прохождения тестов изменения объединяются с основной
веткой. Задача переводится в Done после выполнения всех критериев приёмки.

## Критерии готовности задач

| Ready | Done |
|---|---|
| Понятный результат и критерии приёмки | Критерии приёмки проверены |
| Есть оценка и ответственная роль | Код проверен, тесты пройдены |
| Известны зависимости | Изменение объединено в основную ветку |
| Согласован необходимый контракт | Документация соответствует реализации |

MrDeryf принял приглашение и имеет право записи в основной репозиторий. Приватный CI-репозиторий управляется отдельно.
