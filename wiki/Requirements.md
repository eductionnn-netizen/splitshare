# Требования

## Аудитория

Друзья в поездке, соседи по квартире и небольшие компании, которые регулярно
оплачивают совместные покупки. В примере используются вымышленные данные.

## Пользовательские истории

| ID | История | Проверяемый результат |
|---|---|---|
| US-01 | Как организатор, хочу создать группу | Группа содержит уникальных участников |
| US-02 | Как участник, хочу записать оплаченный расход | Сохранены плательщик, сумма и получатели |
| US-03 | Как участник, хочу понять свою долю | Сумма долей точно равна сумме расхода |
| US-04 | Как участник, хочу увидеть итоговый долг | Показан положительный или отрицательный баланс |
| US-05 | Как участник, хочу рассчитаться без лишней переписки | Есть список «от кого → кому → сколько» |
| US-06 | Как участник, хочу отметить возврат | Подтверждённый перевод меняет баланс ровно один раз |

US-01–US-05 реализованы в прототипе через входной файл и консольный результат;
постоянное хранение и пользовательский интерфейс запланированы. US-06 ещё не реализована.

## Бизнес-правила

1. Валюта первой версии — RUB. Сумма хранится целым числом копеек.
2. В группе нет участников с одинаковым идентификатором; в прототипе идентификатор — имя.
3. Плательщик входит в группу, но может оплатить покупку только для других участников.
4. Сумма расхода строго положительна. Нулевые и отрицательные расходы запрещены.
5. Получатели расхода входят в группу и не повторяются.
6. Расход делится поровну. Остаток по одной копейке получают первые участники в списке.
7. Положительный баланс означает «участнику должны», отрицательный — «участник должен».
8. Предложения переводов не являются реальными банковскими платежами.

## Границы квартального релиза

**Входит:** группы, расходы, балансы, предложения взаиморасчётов, подтверждение
возврата, браузерный интерфейс, тесты, локальная демонстрационная сборка.

**За пределами релиза:** банковская интеграция, мультивалютность, OCR чеков,
распределение по произвольным весам, мобильные приложения, финансовые рекомендации.

## Критерии качества

- Ни одна копейка не теряется при делении.
- Сумма балансов группы всегда равна нулю.
- Некорректный ввод даёт понятное сообщение об ошибке.
- Сборка выполняется одной воспроизводимой последовательностью команд.
- Для будущего API: пользователь видит только свои группы; проверка доступа обязательна.
