# Сценарий защиты практик

## 1. Репозиторий и wiki — 2 минуты

Показать репозиторий SplitShare и приглашённых участников. Открыть главную wiki,
требования и архитектуру. Продемонстрировать заголовки, таблицы, списки, чек-лист,
цитату, блок JSON, Mermaid, формулы и раскрывающийся блок.

Wiki опубликована отдельно: https://github.com/eductionnn-netizen/splitshare-docs/wiki.
Исходники остаются приватными. В Wiki есть 6 страниц и боковое меню. Имена страниц
с дефисами GitHub преобразовал в Unicode-дефис; используйте ссылки из меню Wiki.

## 2. Доска — 2 минуты

Показать 10 Issues из `planning/Backlog.md`, команду, спринт и оценку в описании задач и колонки
Backlog, Ready, In Progress, Review, Done. Открыть одну задачу с критериями приёмки,
зависимостью и связанным PR. Показать реальный переход после успешной проверки.

Объяснение: «Мы работаем двухнедельными спринтами. Доска показывает состояние задач,
а ограничение незавершённой работы помогает доводить изменения до конца».

## 3. Квартальный план — 2 минуты

Открыть `Quarter-plan`: шесть спринтов, три команды, диаграмма Ганта.
Проследить зависимость Backend SS-05 → Frontend SS-07 → QA SS-09.
Объяснить: задержка API переносит интеграцию; mock помогает разработке экрана,
но не заменяет реальную проверку. Показать владельцев зависимостей и резерв квартала.

## 4. Локальная сборка — 3 минуты

Показать работающий self-hosted runner и запустить workflow. В логе открыть имя
компьютера, тесты, сборку и `SMOKE PASSED`. Показать сформированный артефакт.

Затем выполнить:

```bash
python3 dist/splitshare.pyz examples/weekend.json
```

Результат: Вика переводит Ане 1300 ₽, Борис переводит Ане 400 ₽.
Программа лишь рассчитывает переводы — банковских операций нет.
